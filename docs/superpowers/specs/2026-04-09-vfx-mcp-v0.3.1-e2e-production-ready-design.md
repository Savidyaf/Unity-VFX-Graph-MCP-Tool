# v0.3.1 E2E Production-Readiness Sweep — Design

**Date:** 2026-04-09
**Branch:** `vfxgraph-rebuild-v0.3`
**Baseline:** v0.3.1 (115 EditMode tests passing)
**Goal:** Run a full end-to-end exercise of every action in all 9 `vfx_*` MCP tools against a live Unity instance, fix every bug found, and lift every "in-scope deferred item" to production-ready state.

## 1. Background

v0.3.1 shipped on 2026-04-08 with 115 tests green and a Phase 4a backlog largely closed. Several items remain in honest `state="not_implemented"` envelopes (catalog F10, compile-status F4, graph-level setting deflections, F3 partial keys on `get_info`). The package README still describes the legacy `manage_vfx_graph` mega-tool architecture and references files that no longer exist after the v0.3.0 rebuild.

The user wants the package "100% production ready by the end of execution". This means: every action exercised end-to-end, every silent-success bug surfaced, every in-scope deferred item lifted, README rewritten, CHANGELOG updated, all on a single branch with a clean commit trail.

## 2. Locked decisions (from brainstorming)

| Decision | Choice |
|---|---|
| Deferred items | **In scope — fix them now** |
| Coverage depth | **Happy path + error path per action** (~80–120 calls) |
| Agent topology | **Single test agent → parallel evaluator + fix waves** |
| README rewrite | **Yes — rewrite as part of this run** |
| Fixture lifecycle | `Assets/VfxE2EFixtures/`, full cleanup at end |
| Skill location | `.claude/skills/vfx-mcp-e2e-test/` (project-local) |

## 3. Architecture

```
SKILL.md → test agent → JSON report → triage → evaluator subagent (parallel)
                                                       ↓
                                          merged cluster manifest
                                                       ↓
                                          fix subagents (≤4 in parallel/wave)
                                                       ↓
                                          narrow re-test → loop
                                                       ↓
                                       termination → final pass
```

**Components:**
- **Skill** at `.claude/skills/vfx-mcp-e2e-test/` — `SKILL.md` (procedural) + `references/` (data tables: action catalog, error envelope spec, report schema, known-deferred authorization)
- **Test agent** — isolated subagent, executes the skill, produces structured JSON report, never fixes
- **Evaluator subagent** — independent auditor, re-reads the report against `VfxKernelContracts.cs`, catches silent-success bugs the test agent missed
- **Fix subagents** — parallel where possible, one per logical bug cluster, bounded by minimum-fix doctrine and locked-surface constraints
- **Main agent (me)** — orchestrates triage, dispatches subagents, merges results, makes wave-level commits, escalates on hitting termination conditions

## 4. Test agent execution model

**Phases** (sequential, against single evolving `Assets/VfxE2EFixtures/E2EThruster.vfx`):

1. **Discovery** — read-only `vfx_diag.list_*` + `vfx_graph.get_info` on empty state
2. **Asset lifecycle** — `vfx_asset.create/list/assign/delete`
3. **Graph build** — `vfx_node.add` × multiple types + `vfx_block.add` + `vfx_node.connect` + `vfx_node.list`
4. **Mutations** — `set_setting`/`set_property`/`move`/`reorder`/`set_activation`/`set_value`/`set_exposed`/`set_attribute` per type
5. **Batch + recipes + subgraph** — `vfx_batch.commit` multi-tool ops, `vfx_recipe.list`, `vfx_subgraph.create/add_ref/get_exposed/set_override`
6. **Save / compile / health / cleanup** — `save`/`compile`/`get_health`/`discard_changes` + delete fixture folder

**Per-call dispatch:** `mcp__UnityMCP__execute_custom_tool` with `verbose=true` (so the `health` block is auditable). `unity_instance="ca9e7d133faa7c96"`.

**Token table:** agent maintains scratch token-name table across phases (`$spawn_ctx`, `$position_op`, etc.); skill specifies placeholders, not literal tokens.

**Compile/busy guards:**
- Before each mutating phase, poll `mcpforunity://editor_state` until `isCompiling=false`, cap 30s
- On `code="vfx_busy"`, sleep `retry_after_ms` once and retry; second failure → FAIL
- Never call `mcp__UnityMCP__refresh_unity` (invalidates token table)

**Forbidden agent actions:** code edits, test edits, git commands, `refresh_unity`, stopping early on first FAIL.

## 5. Report schema

```jsonc
{
  "phases": [{
    "phase": 1,
    "name": "Discovery",
    "steps": [{
      "step": "1.1",
      "tool": "vfx_diag",
      "action": "list_node_types",
      "params_summary": "page=0 page_size=50",
      "expected": "ok=true, items[] non-empty",
      "observed_keys": ["ok", "items", "tool_version", ...],
      "status": "PASS|FAIL|ANOMALY|SKIPPED",
      "raw_response_excerpt": "...",
      "notes": null
    }]
  }],
  "summary": {
    "total": 0, "pass": 0, "fail": 0, "anomaly": 0, "skipped": 0,
    "known_deferred_seen": [],
    "unexpected_errors": []
  }
}
```

**Status semantics:** `ANOMALY` is the silent-success catcher — the agent must flag responses that look successful but are missing required keys or returned `state="not_implemented"` when implementation was expected.

## 6. Triage and fix waves

**Step 1 — Triage** (main agent): bucket non-PASS rows by `(file_owner, severity)`, build cluster manifest with optional `blocks_clusters` dependencies. Severity scale:
- **P0** — contract violation (response shape wrong, missing `tool_version`)
- **P1** — functional bug (action returns wrong result)
- **P2** — surface gap (in-scope deferred item to lift)
- **P3** — docs/cosmetic

**Step 2 — Evaluator subagent** (parallel with triage): independent audit of the report against the contract. Output is a JSON list of `{step, original_status, true_status, reason}`. Findings merge into the cluster manifest.

**Step 3 — Fix wave** (≤4 parallel fix subagents): each receives one cluster, the bug rows, the owner files, and the rules in §7. Subagents stage files but do not commit. Main agent commits per-wave with single audit-trail commit.

**Step 4 — Re-test** (test agent, narrow): re-run only affected phases + 1 happy-path spot-check from each unaffected phase.

**Step 5 — Termination conditions:**
- All clean (0 FAIL, 0 ANOMALY) → final pass
- 3 fix waves attempted → escalate to user
- Wave reduced FAILs by <20% → escalate to user
- Wave introduced more FAILs than previous → revert wave and escalate

## 7. Fix-subagent guardrails

1. **Minimum-fix doctrine** — no refactors, no drive-by cleanup, no new abstractions. Cap ~30 LOC / 2 files; escalate beyond.
2. **Locked surfaces** — `VfxKernelContracts.cs`, `Editor/Generated/*.g.cs`, soft-fork patches in `Packages/com.unity.visualeffectgraph/`. Touching any of these requires explicit unlock from main agent.
3. **Severity-keyed scope** — P0 fixes shape only, P1 fixes function only, P2 implements within authorized files (per `references/known-deferred.md`), P3 touches docs only.
4. **No new files** unless authorized in cluster manifest.
5. **Test-first for behavioral fixes** — failing-then-passing EditMode test in `Tests/Editor/{Tools|Kernel}/`.
6. **Test count must go up, never down** — 115-test baseline holds; each wave adds tests.
7. **One commit per wave** — main agent aggregates cluster work into one wave-level commit message.

## 8. References authorization document

`references/known-deferred.md` is the single source of truth for which P2 lifts are in scope and which approach to use. One entry per known-deferred item from the v0.3.1 CHANGELOG, with decision = "LIFT" and explicit list of authorized files. Fix subagents check this file before P2 work.

In-scope items to lift in this run (per locked decision):
- `vfx_diag.list_attributes` (F10)
- `vfx_diag.list_settings` (F10)
- `vfx_graph.compilation_status` (F4 — real read of compile errors)
- `vfx_graph.get_health` (F4 — real or honest stub with rationale)
- `vfx_graph.set_capacity` / `set_bounds` / `set_space` — implement against the right `VFXContext` per the F3 spec hint, OR keep the deflection if Unity API doesn't permit
- `vfx_graph.get_info` F3 partial keys (`space`, `bounds_setting_mode`, `update_mode`)
- `vfx_subgraph.inline` / `extract` — only if cleanly implementable; otherwise stays deferred with explicit rationale

## 9. Definition of done

- Final E2E run reports 0 FAIL, 0 ANOMALY across all 6 phases
- Full EditMode test suite green; ≥115 tests
- All in-scope deferred items either lifted or escalated with explicit rationale
- README rewritten against v0.3.1 surface
- CHANGELOG `[Unreleased]` section captures all fixes
- `Assets/VfxE2EFixtures/` cleaned up
- All commits land on `vfxgraph-rebuild-v0.3`; no force-push, no contracts changes
- Skill checked in at `.claude/skills/vfx-mcp-e2e-test/` for future regression runs

## 10. Out of scope

- `package.json` version bump (next phase)
- Cross-Unity-version testing (Unity 6000.4.0f1 only)
- HDRP support (URP-only per package design)
- Performance regression testing (`VfxPerformanceTests` must pass but no new perf budgets)
- Migration tools or backwards-compat shims for the legacy `manage_vfx_graph` action surface (it's already removed)

## 11. Risks

| Risk | Mitigation |
|---|---|
| Domain reload mid-run invalidates the agent's token table | Pre-flight `isCompiling=false` check; never call `refresh_unity` |
| Fix subagent spirals into a refactor | Minimum-fix doctrine + 30 LOC ceiling + escalation path |
| F10 catalog lift hits the same `VFXAttributesManager` reachability problem from v0.3.1 design §4.1 | Same fallback rule: pick highest path that doesn't require new bridge helper; default to hardcoded list with rationale; do NOT add a bridge helper without user approval |
| 3 fix waves runs out before clean | Hard cap; escalate to user with structured "what's left" doc rather than grinding |
| Single wave introduces a regression class | Termination condition + `git revert` (NOT reset) + escalate |
